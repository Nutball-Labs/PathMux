clops_gpsinfo

GPS metadata inspector for dashcam footage segments

Synopsis

clops_gpsinfo [OPTIONS] file.ts
clops_gpsinfo [OPTIONS] MID:TID
clops_gpsinfo --scan-all-trips [OPTIONS]

Description

clops_gpsinfo reads GPS metadata from a dashcam footage segment using ExifTool and reports the GPS lock time, first fix coordinates, and optionally all GPS records. It can also batch-scan every trip across all cached manifests to report seconds-to-GPS-lock for fleet analysis.

The tool operates in three modes:

Single-file mode
Probes one .ts segment and reports the GPS lock event and (optionally) all GPS records from that file.
MID:TID mode
Resolves a manifest trip address to the first Front camera segment and probes that file. Equivalent to passing the absolute path directly.
Batch mode (--scan-all-trips)
Reads all cached manifests, scans the first Front segment of each trip, and prints a table of GPS lock times. Lock times are written back into each manifest for display in the interactive browser and clops_ls.

Options — Single-file and MID:TID

--first-lock
Report the first GPS record with a valid (non-zero) fix. This is the default mode.
--all
Report all GPS records from the segment, not just the first lock.
--json
Output in JSON format (default).
--text
Output in human-readable text format.
--csv
Output in comma-separated values format.
--xml
Output in XML format.

Options — Batch Scan

--scan-all-trips
Scan the first Front camera segment of every trip across all cached manifests. Prints a table showing manifest ID, trip ID, nominal segment duration, seconds to first GPS lock, and the segment filename. Results are written back into each manifest (the gpsLockSeconds field) so subsequent tools do not need to re-scan. Cannot be combined with a file path or MID:TID argument.

Options — Common

--exiftool PATH
Path to the ExifTool binary. Defaults to exiftool (resolved via PATH).
--exiftool-opts OPTIONS
Override the ExifTool options string. Defaults to the gps_exiftool_args value from the camera profile embedded in the manifest, or the built-in profile default if no manifest profile is present.
-v, --version
Print the CamClops version string and exit.
-h, --help
Print a usage summary and exit.

GPS Lock

GPS receivers require time to acquire a satellite fix after power-on (cold start). The Pruveeo D90 firmware does not write GPS records to the LIGO stream until a satellite fix is acquired, so there are no pre-lock zero-position records in the stream.

Lock time is computed by comparing the UTC timestamp of the first valid GPS record against the clip-start time encoded in the filename (local time), using epoch arithmetic to handle timezone differences correctly. The result is stored as gpsLockSeconds in the trip manifest.

Automatic computation (v1.9.0+): When GPS is extracted from the GUI (Trip Properties → GPS tab), gpsLockSeconds is computed and stored automatically as part of the extraction. Running --scan-all-trips is no longer required for trips extracted via the GUI. Use --scan-all-trips for batch operations or to refresh lock times on trips extracted with an older version of CamClops.

gpsLockSeconds = 0
The receiver already had a fix at the start of the clip (warm start). Typical cold-start values on the D90 are 20–120 seconds.
gpsLockSeconds = none (or -1)
No valid GPS fix was found in the segment at all. This is normal for very short stub segments recorded at startup before the receiver acquired a lock.

Output Formats

JSON (default)

{
  "file": "/path/to/Front/20260209_043838F.ts",
  "total_records": 147,
  "first_lock_record": 0,
  "first_lock": {
    "timestamp_utc": "2026:02:09 10:39:14",
    "record_index": 0,
    "lat": 30.419000,
    "lon": -89.025191
  }
}

Text

File:           /path/to/Front/20260209_043838F.ts
Total records:  147
Valid fixes:    147  (100% coverage)
First lock:     record 0  (0s after segment start)
  Timestamp:    2026:02:09 10:39:14
  Position:     30.419000, -89.025191
  Speed:        0.0 km/h
  Heading:      0.0°

In --all mode the text report also shows the last fix and a GPS dropout count.

Scan-All-Trips Output

MID  TID  SegDur  LockAt  First Segment
---  ---  ------  ------  --------------------
CY   7E     180s      0s  20260225_044424F.ts
CY   3Z     180s    none  20260225_035430F.ts

SegDur is the nominal segment interval derived from filename timestamp spacing. LockAt is seconds to first GPS fix (0s = immediate; none = no fix found).

Notes

Timestamps in GPS output use the format YYYY:MM:DD HH:MM:SS in UTC, as returned by ExifTool. Filename timestamps are in local time.

Speed is reported in km/h. Altitude is present in the GPS stream but known incorrect on the Pruveeo D90 (returns negative values at sea level) and is therefore not reported.

Files

~/.config/camclops/camclops.json
Application settings including exiftoolPath. GPS extraction arguments are stored in the camera profile, not in global settings.
~/.config/camclops/manifests.json
Manifest index used by MID:TID resolution and --scan-all-trips.

Exit Status

0
Success.
1
Failure (bad arguments, file not found, ExifTool error, or MID:TID not resolved).
