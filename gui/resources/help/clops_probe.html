clops_probe

Camera compatibility profiler for the CamClops suite

Synopsis

clops_probe [--json] file.ts
clops_probe [--json] MID:TID
clops_probe --card PATH [--json]
clops_probe --wizard PATH

Description

clops_probe inspects dashcam footage files and reports video characteristics, stream layout, and GPS metadata format. It is primarily intended to help users determine whether an unsupported camera model is compatible with CamClops, and to collect the information needed to request support for a new camera via a GitHub issue.

Single-file and MID:TID modes probe one segment and print a concise report.

Card mode (--card) walks an entire dashcam storage root, identifies camera subdirectories, samples segment durations, and probes the first segment of the primary camera directory. The report is formatted to be pasted directly into a GitHub issue.

Options

file.ts
Probe a single footage segment. The path must be absolute or resolvable from the current directory.
MID:TID
Probe the first Front camera segment of a known trip identified by its manifest ID and trip ID. Uses the CamClops manifest index to resolve the segment path.
--card PATH

Fingerprint a dashcam storage root. PATH should be the top-level directory that contains the camera subdirectories (Front/, Rear/, etc.).

Candidate camera directories are identified as any first-level subdirectory of PATH that contains video files. If no subdirectories contain video files but PATH itself does, the root is treated as a flat single-directory layout and camera identity is inferred from filename tokens. Supported token styles include bare single-letter suffix (F, R, L, B), underscore-prefixed letter (_F, _R), multi-part embedded tokens (_CAM1_VID, _CAM2_VID), and prefix tokens where the camera identifier precedes the timestamp.

Hidden files and macOS resource forks (names beginning with .) are ignored during all scans. Up to five segments are sampled for duration measurements; the full probe is performed on the first segment of the primary camera directory.

--json
Emit JSON output instead of the default text report. Suitable for automated processing.
--wizard PATH

Interactive camera profile builder. Walks the dashcam storage root at PATH and guides the user through:

  • Camera role assignment (Front/Rear/Left/Right) — from subdirectory names for cameras that use a directory per channel, or from filename tokens for cameras that store all channels in one directory. A two-pane interface shows the standard slot names on the left and the detected source paths with sample filenames on the right; press F/R/L/B to select a slot then a source number to assign it.
  • Filename timestamp format and timestamp timezone (local or utc).
  • Thumbnail handling — sidecar _ths.jpg files detected automatically; falls back to generate-on-demand via ffmpeg if not found.
  • GPS method and cold-start lock offset.
  • Profile name.

On completion the profile is saved in CameraProfile JSON format to ~/.config/camclops/profiles/<name>.json and a trial scan is run immediately to confirm that the saved profile detects trips correctly.

-v, --version
Print the CamClops version string and exit.
-h, --help
Print a usage summary and exit.

GPS Method Values

LIGOGPSINFO
The file contains a private binary data stream tagged LIGO in the container. This is the format used by Pruveeo D90 footage. ExifTool must support the LIGOGPSINFO stream format for extraction to work. If GPS extraction fails for your camera, contact the ExifTool maintainer directly.
Standard GPS metadata
GPS metadata was successfully extracted by ExifTool using the configured extraction options, but no LIGO private data stream was detected. The camera uses a standard or otherwise identifiable GPS metadata format.
Not detected
No GPS data was found. Either the camera does not record GPS, the footage was recorded without a GPS fix, or the camera profile's GPS extraction arguments are incompatible with the camera's GPS format.

Examples

Probe a single file:
clops_probe /mnt/sdcard/Front/20260209_043838F.ts
Probe a trip's first segment via MID:TID:
clops_probe X1:87
Fingerprint an entire SD card:
clops_probe --card /mnt/sdcard
Machine-readable card fingerprint for a GitHub issue:
clops_probe --card /mnt/sdcard --json
Create a camera profile interactively and verify with a trial scan:
clops_probe --wizard /mnt/sdcard

Requesting Camera Support

If your dashcam is not supported, first try the wizard:

clops_probe --wizard PATH

If the wizard does not produce a working profile, collect a fingerprint and open a GitHub issue:

clops_probe --card PATH --json > camera_report.json

Open a GitHub issue at https://github.com/Nutball-Labs/CamClops/issues and attach camera_report.json. Include the camera make and model in the issue title.

Files

~/.config/camclops/manifests.json
Manifest index — used only when resolving MID:TID arguments.
~/.config/camclops/profiles/<name>.json
Camera profile written by --wizard. Loaded by camclops when the active profile ID matches <name>.

Exit Status

0
Probe completed successfully (GPS may or may not have been found).
1
Invalid arguments, file not found, or MID:TID not in the manifest index.
