PathMux GUI Overview

pathmux-gui — Qt6 desktop interface for dashcam trip management

Main Window Layout

The main window is a horizontal split view:

  • Left panel (Manifest Panel): Lists all known footage sources (manifests). Each entry shows the footage path, number of trips, and date range.
  • Right panel (Trip Grid): Shows trip tiles for the selected manifest. Each tile displays the trip date, start time, duration, segment count, and a thumbnail from the trip.

Drag the center divider to resize the panels. Use Ctrl+Scroll over either panel to zoom the tile size.

Scanning Footage

To add a footage source:

  1. Use Manifests > Scan Source Directory (or Ctrl+O).
  2. Navigate to the top-level dashcam footage directory (the one containing Front/, Rear/, etc. subdirectories).
  3. Click OK. A progress dialog shows scan status.
  4. When complete, the manifest appears in the left panel and its trips appear in the right panel.

Each footage directory contains a single pm_manifest_XX.json file shared by all platforms. If the same footage is accessible from Linux, Windows, and macOS (for example, on a NAS or shared drive), each platform registers its local path automatically when it opens the directory — no manual configuration required. Segment file paths are stored relative to the source root so the manifest works correctly regardless of drive letter or mount point.

Viewing Trips

Click a manifest in the left panel to load its trips. Each trip is shown as a tile in the right panel with:

  • Date and start time
  • Duration and segment count
  • Distance (if GPS data has been extracted)
  • GPS status indicator
  • Thumbnail image from the trip

Double-click a trip tile to open the Trip Properties dialog.

Trip Properties Dialog

The Trip Properties dialog is tabbed:

  • Info: Trip metadata — date, start time, duration, segment count, distance. Segment list; double-click a segment to open it in the system video player.
  • GPS: GPS status, lock time, start/end coordinates. Extract GPS button runs ExifTool against the footage. Export buttons produce GPX, KML, and GeoJSON files.
  • Map: Generate a GPS-synced overhead moving map as an MP4. The map video is stored alongside the footage and tracked in the manifest. Double-click a listed file to open it in the system viewer.
  • Dashboard: Generate an animated instrument dashboard video (speed, heading, trip odometer, weather). Weather data from Open-Meteo archive API — no account or key required. Requires GPS to be extracted first.
  • HUD: Generate a military-style heads-up display as a transparent WebM (VP9/alpha). Elements: left speed tape (KPH), right speed tape (MPH), circular compass rose at bottom-center. Elements float over camera footage with no opaque background — designed for full-frame compositing over the collage output. Style, tape dimensions, and compass position are configurable per-trip; global defaults are set in Tools > Settings > HUD. Requires GPS to be extracted first.

Map, Dashboard, and HUD generation each show a progress dialog with a Cancel button. All prompt before overwriting an existing output file.

GPS sync note: The map and HUD overlay are timed relative to the video using gpsLockSeconds — the number of seconds from trip start until the first GPS satellite fix. This value is computed automatically when you extract GPS from the GUI. If the map or HUD appears offset from the video, re-extract GPS for that trip to refresh the value.

Video Build Dialog

Open via Build Video in Trip Properties, or Trips > Build Video from the main menu.

Collage Layout tab

Shows a dark-themed 2×2 grid matching the collage output layout:

  • Top-Left = Front camera
  • Top-Right = Rear camera
  • Bottom-Left = Right camera
  • Bottom-Right = Left camera

Each quadrant has a checkbox (top label) and a source combo. The checkbox unchecked or "None" selected → that quadrant plays the PathMux/Nutball-Labs logo morph animation in the built video (a 6-second looping cross-fade, not a black frame). The combo lists:

  • All cameras present in the trip — any camera can fill any position. The native camera for that position is marked ★. Putting the Front camera in all four quadrants is valid.
  • Any map or dashboard MP4 files already generated for this trip.
  • External video… — browse to any video file on disk.
  • None (logo morph) — plays the branded animation.

The centre overlay cell (between the quadrants) configures an optional video composited at 960×540 centred over the 4K output. Intended for map and dashboard videos. Selecting None with the overlay enabled uses the logo morph as a looping branded watermark on the finished video.

Below the grid:

  • HUD overlay (full-screen): checkbox to composite a transparent HUD WebM (VP9/alpha) at full 3840×2160 over the entire collage output. The HUD elements (speed tapes, compass rose) float over all four camera quadrants with genuine alpha transparency. This is separate from the centre overlay — enabling both applies the map/dashboard inset first, then the HUD on top. If no HUD video has been generated for the trip yet, enabling the checkbox prompts you to build one first in Trip Properties → HUD tab.
  • Collage audio from: which quadrant provides the audio track.
  • Build: 4K (3840×2160 H.265) and/or 1080p downscale checkboxes.
  • Preview Frame… — grabs one frame per active slot via ffmpeg and shows a 960×540 composite preview of the collage layout before you commit to a full build. The HUD overlay is also composited into the preview with correct alpha transparency. Takes a few seconds per slot.

Camera Files tab

Controls individual per-camera output files (independent of the collage):

  • Front / Rear / Left / Right checkboxes — each produces a single concatenated MP4 for that camera.
  • Container format (mp4, mkv, mov).
  • Audio extract — pull the audio track from a chosen camera to a standalone m4a, mp3, or aac file.

Output tab

Set the destination directory and an optional basename prefix. If left blank, the output directory defaults to the footage source path and filenames are prefixed with the trip date and time.

Action row

Process Now starts the build immediately. Add to Batch Queue queues the build job for later execution, including on other machines that share the same footage via a network path. The Verbose output checkbox streams all ffmpeg stderr to the progress dialog log panel — useful for diagnosing encode failures.

Build Progress Dialog

Shows one row per build stage. Per-camera concat stages run concurrently. Click the X button at any time to cancel — the current ffmpeg process is killed cleanly and all remaining stages are skipped.

Tools

Settings… (Ctrl+,)
Open the Settings dialog to configure ffmpeg path, ExifTool binary path, default export directory, active camera profile, encoder preset, and UI scale. ExifTool GPS options are no longer a global setting — they are stored per camera profile (see Camera Profiles).
Setup Wizard…
Re-run the first-run setup wizard. Pre-populated with current settings so you can update specific fields (e.g. swap the encoder preset after adding a GPU) without reconfiguring everything.
Camera Profiles…
Manage camera profiles. Lists all built-in and user profiles.
  • Fork as Custom — create an editable JSON copy of a built-in profile in ~/.config/pathmux/profiles/. Edit it with any text editor, then rescan footage to embed the updated profile.
  • Open in Editor — open a user profile in the system default editor.
  • Set as Active — set the selected profile as the default for new scans (shown with a ★ in the list).
  • Delete — remove a user profile file. Built-in profiles cannot be deleted, but can be overridden by forking them.
Manifests that already have an embedded profile snapshot are unaffected by profile changes until the footage directory is rescanned.
Probe SD Card…
Run pm_probe --wizard against an SD card to create or update a camera profile.

Settings Dialog

The Settings dialog covers:

  • Paths: ffmpeg binary, ExifTool binary, default export directory
  • Camera Profile: active profile ID used when scanning new directories with no existing manifest. Manage profiles in Tools > Camera Profiles.
  • Display: imperial/metric units toggle; UI scale factor (1.0–3.0, requires restart)
  • Encoder: preset selection and individual encoder parameters (host-specific; saved to the host overlay file)

Setup Wizard

The Setup Wizard walks through the minimum configuration needed to get started:

  1. ffmpeg and ExifTool binary paths
  2. Default export directory for GPS tracks and video files
  3. Encoder preset (CPU / VAAPI / NVENC / QSV)

The wizard can be re-run at any time from Tools > Setup Wizard. It pre-populates all fields with the current saved settings.

First-Run Behavior

On first launch (no config file found), the Setup Wizard runs automatically. Complete the wizard to configure your system, then use Manifests > Scan Source Directory to add your first footage source.

GPS Cold-Start Warning

Important: Dashcam GPS receivers typically require 30–120 seconds to acquire a satellite fix after power-on. No GPS data is recorded during this period. If you use GPS track data for mileage logs, tax records, or legal documentation, be aware that the first portion of every trip may be missing from the GPS track. The distance shown in PathMux is great-circle distance between first and last recorded fix — not total odometer distance.
