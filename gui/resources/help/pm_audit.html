pm_audit

Footage integrity checker for PathMux manifests

Synopsis

pm_audit [--deep] [--json] [MID | MID:TID]

Description

pm_audit walks cached PathMux manifests and verifies that the source footage files are still accessible and unmodified. It catches common operational problems: storage not mounted, SD card swapped or reformatted, files deleted or corrupted.

Each trip contains a small validation sample — three footage files selected at scan time with their MD5 checksums recorded in the manifest. pm_audit checks that each sample file still exists at the expected path and that its checksum matches the recorded value.

pm_audit does not write to any manifest. It is purely read-only and safe to run at any time, including from cron.

Options

--deep
Also run ffprobe on every Front camera segment of every trip to detect truncated or corrupt video files that pass the MD5 sample check. This mode is significantly slower on large collections — a confirmation prompt is shown before proceeding when auditing more than five trips without a filter.
--json
Emit JSON output. The top-level object contains total_trips, problem_trips, all_ok, and a manifests array. Suitable for scripting and pipeline use.
-v, --version
Print the PathMux version string and exit.
-h, --help
Print a usage summary and exit.

Trip Status Values

OK
All validation sample files are present and their MD5 checksums match the values recorded at scan time.
MISSING
One or more validation files were not found on disk. Typical causes: storage drive not mounted, SD card removed, or files deleted. The filename of the first missing file is shown in parentheses.
MODIFIED
All validation files are present but at least one checksum does not match. The file exists but its contents have changed since the manifest was written. Typical causes: partial write during recording failure, filesystem corruption, or deliberate replacement.
NO_VALIDATION
The trip has no validation sample recorded. This affects trips scanned before the validation feature was added. Re-scan the footage path with pathmux -s to populate validation data.
CORRUPT
(--deep only) All validation sample checks passed but ffprobe reported an error or zero duration on a segment. Indicates a truncated or unreadable video file that happens not to be in the validation sample.

Output — Text (default)

[X1]  /z/srcdash/ex2
  X1  87  OK          2026-02-09  04:38:38  14 segs
  X1  37  MISSING     2026-02-10  14:31:41  16 segs  (Front/20260210_143141F.ts)

1 of 2 trips have problems.

A manifest header line ([MID] path) precedes each manifest's trips.

Output — JSON

{
  "all_ok": false,
  "total_trips": 2,
  "problem_trips": 1,
  "manifests": [
    {
      "id": "X1",
      "path": "/z/srcdash/ex2",
      "manifestFile": "/z/srcdash/ex2/pm_manifest_X1.json",
      "trips": [
        {
          "mid": "X1", "tid": "87",
          "date": "2026-02-09", "start_time": "04:38:38",
          "seg_count": 14,
          "status": "OK", "detail": ""
        }
      ]
    }
  ]
}

Examples

Audit all manifests:
pm_audit
Audit one manifest:
pm_audit X1
Audit one trip:
pm_audit X1:87
Deep check with ffprobe on all segments:
pm_audit --deep X1
Machine-readable output for scripting:
pm_audit --json
Use in a script — non-zero exit means problems:
pm_audit --json > audit.json
if [ $? -ne 0 ]; then
    echo "Footage integrity problems found" >&2
fi

Files

~/.config/pathmux/manifests.json
Manifest index.
<footage_path>/pm_manifest_<id>.json
Trip manifest containing the validation sample and checksums.

Exit Status

0
All audited trips passed.
1
One or more trips have a problem (MISSING, MODIFIED, NO_VALIDATION, or CORRUPT). Use --json for machine-parseable detail.
