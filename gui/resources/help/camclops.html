camclops

Trip manager and video builder for multi-channel dashcam footage

Synopsis

camclops [OPTIONS] [PATH]

Description

camclops scans dashcam footage directories, groups video segments into trips based on timestamp gaps, and caches the results as JSON manifests. Trips can be browsed interactively, exported as GPX or KML tracks, and assembled into per-camera MP4 files or a synchronized 4K collage.

CamClops uses camera profiles to support different storage layouts. The built-in profile targets the Pruveeo D90 360° four-channel dashcam (Front, Rear, Left, Right subdirectories; MPEG-TS container; LIGO GPS stream). Additional profiles for other cameras can be created interactively with clops_probe --wizard.

The primary camera is the anchor for trip detection; secondary cameras are fuzzy-matched within a configurable time window. All timestamp comparisons use Unix epoch arithmetic to handle midnight and year boundaries correctly.

Trip manifests are written to the scanned footage directory as clops_manifest_<id>.json. If that directory is not writable, manifests fall back to ~/.config/camclops/. Each scanned path is assigned a two-character alphanumeric manifest ID from an unambiguous character set (ambiguous pairs such as O/0 and I/1 are collapsed).

Options — Scan & Display

-s PATH, --scan PATH
Scan PATH for dashcam footage and build a trip manifest. If a manifest already exists for this path, prompts with three choices: overwrite it, delete it and rescan from scratch, or quit. Prints a one-line summary per trip on completion.
-t
Print a compact one-line summary for each cached manifest, sorted by most recent trip date. Shows manifest ID, footage path, trip count, and date range. Non-interactive; exits after printing.
-T, --dump
Print a multi-line block per manifest listing every trip: date, start time, duration, and segment count. No segment file paths are shown. Non-interactive; exits after printing.
--fulldump
Like -T but includes all segment file paths for every trip and every camera.
--jsondump
Dump all manifest and trip data as a single JSON document to stdout. Segment paths are relative to each manifest's source path. Suitable for piping to jq or scripting.
-T --format=fmt
Structured output modifier. Used together with -T. Valid values: json, csv, xml.
json
Equivalent to --jsondump; --fields is ignored.
csv
One record per trip, comma-separated. A header row is emitted first. Use --fields to select columns.
xml
One <trip> element per trip inside a <trips> root. Use --fields to select child elements.
--fields=f1,f2,...
Comma-separated list of fields to include in csv or xml output. Ignored for json. Available fields:
manifest_id, trip_id
Manifest and trip identifiers.
address, date, start_time, start_epoch
Human-readable address (if geocoded), calendar date, wall-clock start time, and Unix epoch of trip start.
duration, duration_seconds
Trip length as formatted string and raw seconds.
segment_count, note
Number of video segments; optional free-text note.
start_lat, start_lon, end_lat, end_lon
Start and end coordinates in decimal degrees (requires GPS extraction).
distance_km, distance_mi
Great-circle distance between start and end coordinates.
gps_lock_seconds
Seconds from segment start until first GPS fix. Requires GPS extraction; zero if not yet run.
gps_track_status
One of none, partial, or complete.
-I, --interactive
Unified interactive browser. Opens at the manifest list home screen. Select a manifest by ID to view its trips; select a trip by ID to view details, build video, or export GPS data. Press Q at any prompt to return to the previous level or exit.

CamClops defaults to the footage source directory if writable. If not writable, a three-choice prompt appears: use the global default export directory, enter a path manually, or return to the trip picker. Accepts a directory path or a full file path ending in .gpx, .kml, or .geojson.

Video Build

Video builds are launched from within the interactive browser (-I). Select a manifest, then a trip, then choose [V] Build video from the trip detail screen.

GO
Run the configured build and return to the trip picker on completion.
GODONE
Run the configured build and exit the video builder on completion.
[T] Compute duration
Run ffprobe on every Front camera segment to produce an accurate total trip duration. Stored in the manifest for future sessions.

A build log entry is appended to clops_buildlog.json in the footage source directory after each successful build.

Video Build Pipeline

Per-camera files use the ffmpeg concat demuxer with stream copy (-c copy). Only video and audio streams are mapped; the LIGOGPSINFO data track is discarded.

The 4K collage is assembled as follows:

  1. Per segment, ffprobe measures the frame count of all four cameras.
  2. Camera sync is applied in two tiers.
    • Tier 1 (always active): ffprobe measures the exact playback duration of each segment and passes it to the concat demuxer via -t flags, preventing drift from startup-lag frame-count differences accumulating across a long trip.
    • Tier 2 (when sync data is present): If the manifest contains a cameraSync block (written by clops_sync_analyze.py), each camera stream is delayed or held using a subdued first-frame ghost pad (brightness −0.25, saturation 0.1) so all streams start at exactly the same wall-clock moment. Zero frames are discarded; all four streams remain lockstep. Silent audio padding (apad) matches each camera's audio duration to its video track. Falls back to Tier 1 only when no sync data is present.
    • Multi-startup trip drift normalization: When a trip contains multiple camera restarts grouped together (inter-restart gaps under the gap threshold), cameras that started later within a given startup record shorter raw segments. Each camera's raw segment duration is probed and extra clone frames are appended to any camera whose raw duration is shorter than the front camera's for that segment, preventing cumulative drift across the trip.
  3. The four normalized streams are combined with the xstack filter into a 3840×2160 frame:
    [ Front ] [ Rear  ]
[ Right ] [ Left  ]
  4. Audio is taken from the configured collage audio source (default: Left camera — the driver position in left-hand-drive countries).
  5. Output is encoded as H.265 (libx265 -crf 18 -preset slow) by default. Hardware acceleration profiles (VAAPI, NVENC) can be configured via --encoderprefs.

The optional 1080p collage is a simple transcode of the finished 4K master (scale=1920:1080, libx264 -crf 20 -preset fast) with the audio stream copied without re-encoding.

GPS Extraction

GPS extraction uses ExifTool to read GPS metadata from footage segments. CamClops reads GPS extraction arguments from the camera profile embedded in the manifest (gps_exiftool_args) and passes them to the ExifTool binary. It does not validate the ExifTool version.

GPS cold-start data gap warning: Dashcam GPS receivers typically require 30–120 seconds to acquire a satellite fix after power-on. No GPS data is recorded during this period. The gps_lock_seconds field in the manifest records how long the gap was for each trip. If you use GPS track data for mileage logs, tax records, or legal documentation, be aware that the first portion of every trip may be missing from the GPS track. The distance reported by CamClops is the great-circle distance between the first and last recorded fix, not the total odometer distance.

Altitude values from the D90 are systematically incorrect (negative) and are ignored. Speed is recorded in km/h.

GPS Arguments — Per-Camera Profile

GPS extraction arguments are stored in the camera profile, not in global preferences. Each profile carries a gps_exiftool_args field that holds the complete ExifTool option string for that camera's GPS format. At scan time this is baked into the manifest, so every GPS operation on that footage automatically uses the correct command regardless of the active global profile setting.

Built-in profiles and their GPS arguments:

Pruveeo D90 (pruveeo_d90)
-ee3 -p '$GPSDateTime $GPSLatitude# $GPSLongitude# $GPSAltitude# $GPSSpeed# $GPSTrack# $Accelerometer'
LIGOGPSINFO binary stream embedded in MPEG-TS. Requires -ee3 to reach the private stream. Accelerometer data available.
Cobra GPS (cobra_gps)
-ee -p '$GPSDateTime $GPSLatitude# $GPSLongitude# $GPSAltitude# $GPSSpeed# $GPSTrack#'
Standard GPS0 atom in MOV/3GP container. -ee (depth 1) is sufficient. No accelerometer data on this camera.

To customise GPS arguments for a specific camera, use Tools > Camera Profiles, select the profile, click Fork as Custom, edit the gps_exiftool_args field in the JSON file, and rescan the footage directory to embed the updated profile.

The output parser expects the following space-separated fields per line (after the date and time token): latitude, longitude, altitude, speed (km/h), heading (degrees). Accelerometer fields (accelX accelY accelZ) are optional and are omitted for cameras that do not record them. Field order is fixed.

Manifest IDs

Manifests are assigned two-character IDs from an unambiguous alphanumeric character set. Excluded characters: O (same as 0), I and L (same as 1), S (same as 5), Z (same as 2).

IDs are always displayed in upper case. Input is case-insensitive. The preferred sequence assigns a letter first character and digit second character (A3, A4 … Y9) giving 132 slots before spilling into letter+letter combinations. Deleted manifest IDs are returned to the pool and reused from the lowest available position.

Trips within a manifest are also assigned two-character base36 IDs. A specific trip can be referenced as MID:TID (e.g. CQ:73) in tool output and future batch operations.

Files

~/.config/camclops/profiles/<name>.json
Camera profiles created by clops_probe --wizard. The active profile is selected by setting activeProfileId in preferences.
~/.config/camclops/camclops.json
Application settings (base preferences, all hosts).
~/.config/camclops/camclops_hostname.json
Host-specific settings overlay written by --hostprefs. Merged on top of the base preferences at startup; only the current machine's file is loaded.
~/.config/camclops/manifests.json
Manifest index — maps each scanned footage path to its two-character ID.
<scanned_path>/clops_manifest_<id>.json
Cached trip manifest written to the scanned directory. Written to ~/.config/camclops/ if the scanned directory is not writable.
~/.config/camclops/manifests_stale.json
Archive of stale manifest index entries. Display with --show-stale; wipe with --clear-stale.
~/.config/camclops/locations.json
Named locations (Home, Work, etc.) used for KML proximity pin overlays.
<scanned_path>/clops_thumbs_<id>/
Thumbnail cache directory written by the GUI when trip tiles load for cameras that do not produce JPEG sidecar files (e.g. Viofo). Thumbnails are stored as tid_slot.jpg. Co-located with the manifest file; cleaned up automatically if the manifest is deleted. Not written by the CLI.
<scanned_path>/clops_buildlog.json
Build provenance log appended after each successful video build. Records build timestamp, manifest ID, trip ID, output path, output duration, cameras included, and source segments consumed.

0
Success.
1
Failure (bad arguments, missing path, or ffmpeg/ExifTool error). --validate exits 1 if any manifest problems are found.
